# MSF Control Panel

Веб-панель для наблюдения и управления пайплайном. Запуск:

```bash
python -m msf.panel.server          # http://127.0.0.1:8765
python -m msf.panel.server --port 9000
```

## Зачем

Всё, что показывает панель, уже было в репозитории и было невидимым. В библиотеке
38 сцен, 96 эффектов, 12 переходов, 38 SFX и 16 музыкальных подложек — узнать это
можно было только чтением TypeScript. Именно поэтому пайплайн неделями крутил пять
пресетов и озвучивал женским голосом, который никто не выбирал: ничего не
показывало, что доступно и что реально используется.

Панель — это **представление над источником**, а не второй каталог:

| Раздел | Источник данных |
|---|---|
| Сцены | `msf.registry` → `remotion/src/registry/*.ts` (тот же файл, что импортирует рендерер) |
| Эффекты, переходы | `msf.registry.load_effects()` / `transition_names()` |
| Голоса | `assets/voices/voices.json` через `resolve_voice`/`describe_reference` |
| SFX, музыка | `msf.audio.sfx.SFX_REGISTRY`, `msf.audio.music.MUSIC_REGISTRY` |
| Граф | `add_node()` вызовы в `build_msf_graph()` |
| LDR | `msf.skills_bridge.deep_research` |

Дублирующегося инвентаря нет. Если панель это показывает — рендерер это отрендерит.
`tests/test_panel_api.py` сверяет каждый эндпоинт с реестром, а
`tests/test_registry_parity.py` сверяет python-парсер с настоящим вычислением TS
через node.

## Что важно понимать в интерфейсе

**`в ротации` ≠ `rotation_safe`.** Реестр помечает 13 пресетов как не требующие
данных, но четыре из них рисуют убедительный вымысел: ScoreHud показывает
`PLAYER 1 / СЧЁТ 9750`, SubscribeCTA — `TechChannel / 142.0K подписчиков`,
BankCard — `ALEXEY NIKITIN / ···· 4242`, CountdownHero вообще игнорирует текст и
пишет `СТАРТ`. Подставлять их автоматически = ставить выдуманные факты в кадр,
против чего и существует `node_deep_research`. Они помечены `свой демо-контент` и
доступны только при явном указании с данными.

**`ICL` против `x-vector`.** Голос без транскрипта в реестре уходит в
`x_vector_only_mode`: тембр копируется, интонация — нет. Отличие слышно, но
обнаруживается только после рендера, поэтому режим показан на карточке, а форма
добавления голоса требует транскрипт и отказывается создать запись без него.

**Переходы — не эффекты.** `EffectStack` ищет имя в трёх реестрах эффектов;
название перехода в `scene.effects` молча игнорируется с предупреждением в
консоли. Поэтому они в отдельном блоке.

## Предпросмотр

Всё рендерится тем же кодом, что и пайплайн — у панели нет своего рендерера,
иначе «в панели выглядело нормально» перестало бы что-либо значить.

- сцены → `remotion/scripts/stress.mjs` (один кадр, ~20–40 с: Remotion пересобирает бандл)
- голос → `synthesize_voice_clone` (~45 с на фразу, грузит модель на CUDA)
- SFX и музыка → `msf.audio` (мгновенно, чистый numpy)

Перед рендером сцены спек проходит `validate_spec`. Без этого пресет с неверной
формой строк отрендерил бы красную ERROR-карточку, и панель показала бы её как
рабочий предпросмотр.

## Прогоны

`POST /api/graph/run` запускает `msf/panel/run_job.py` **отдельным процессом**:
граф грузит 1.7B TTS на CUDA и вызывает Remotion с ffmpeg, в потоке это
заблокировало бы event loop на минуты, а CUDA OOM уронил бы панель. Прогресс
парсится из stdout (`[<node>] done`, `OUTPUT: <path>`, `ERROR: ...`), stdout
читается отдельным потоком — читать пайп в обработчике запроса означало бы висящий
HTTP-запрос на всё время тихого рендера.

## Безопасность

**Аутентификации нет.** Панель слушает 127.0.0.1 и не должна выставляться наружу:
эндпоинты предпросмотра запускают node и ffmpeg, `/api/graph/run` стартует полный
рендер, а `POST /api/voices` пишет файлы в репозиторий. `--host` принимается для
локальной отладки и печатает предупреждение.

Отдача файлов предпросмотра (`/preview/{kind}/{filename}`) проверяет `kind` по
белому списку и разрешает путь внутри кэша — оба сегмента приходят из сети.
