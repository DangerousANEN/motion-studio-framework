## 6.0. ПРОБЛЕМА (сформулирована пользователем, подтверждена замером)

Три отдельные болезни, которые в текущем коде сливаются в одну:

1. **Все ролики одинаковые по структуре.** Пять сцен, всегда
   `хук → механика → цифра → сравнение → CTA`. Причина: единственный источник
   структуры — вручную написанный `STORYBOARD` в `render_promo_shorts.py`, а в
   графе — `node_script_split` с ротацией по трём текстовым пресетам.
2. **Визуал не подходит под текст.** Пресет выбирается ротацией, а не смыслом
   реплики. `TokenCloud3D` встаёт под фразу про экономию времени, потому что
   пришла его очередь, а не потому что она про векторы.
3. **Сцен объективно мало.** 11 пресетов, из них реально несущих данные — 6.
   Для 30-секундного ролика на 5–7 сцен это значит, что второй ролик подряд
   неизбежно повторяет первый.

## 6.2.1. ОГРАНИЧЕНИЯ ВЕРТИКАЛЬНОГО ФОРМАТА

### Safe-zones 1080×1920 — обязательны для всех сцен

Интерфейс площадок перекрывает края кадра, поэтому текст живёт только в
центральном боксе:

```
+------------------------------------------+  0
|      верх: поиск, статус-бар             |  280   ← ничего важного
| - - - - - - - - - - - - - - - - - - - - -|
|                                          |
|          SAFE ZONE (текст, цифры)        |
|                                          |
| - - - - - - - - - - - - - - - - - - - - -|  1540
|   ник, описание, кнопки лайка/шера       |  1920  ← ничего важного
+------------------------------------------+
```

- Верхний отступ **280 px**, нижний **380 px**, боковые **80 px**.
- Фокусный бокс: `X 80…1000`, `Y 350…1540`.

**Найдено при проверке: три несогласованных источника отступов.**

| Где | Значения | Подключено к рендеру |
|---|---|---|
| `VideoSpec.schema.ts` → `safeMargin` | `120` со всех сторон | да |
| `msf/libraries/typography_library.py` | `top 140, bottom 240, left/right 56` | **нет** — в графе не используется |
| Требуется для площадок | `top 280, bottom 380, side 80` | — |

Ни один из существующих наборов не защищает низ кадра: `120` и даже `240`
меньше нужных `380`, поэтому подписи упираются в ник и кнопки. Примитив
`SafeArea` должен стать единственным источником правды, а
`typography_library` — либо подключиться к нему, либо быть удалён как мёртвый
код (сейчас это второй параллельный контракт, который никто не исполняет).

### Читаемость на телефоне — по типам графиков

| Тип | Вертикаль | Условие пригодности |
|---|---|---|
| Progress ring / donut | ✅ | кольцо 30–40 px, цифра 72–90 px, ≤ 2 сегмента |
| Gauge / спидометр | ✅ | пружинный овершут стрелки, градация цвета |
| Парные бары | ✅ | подписи внутри баров, не на оси |
| Вертикальный таймлайн | ✅ | строго сверху вниз, карточки по бокам оси |
| Линейный график | ✅ | 1–2 линии, толщина 6–8 px, без сетки |
| Bar chart race | ⚠️ | ≤ 6 полос, шрифт ≥ 36 px |
| Waterfall | ⚠️ | вертикальный, ≤ 5 ступеней |
| Radar | ⚠️ | ≤ 5 осей, иконки вместо подписей |
| Heatmap | ❌ | только зум 4×4 с крупными числами |
| Treemap | ❌ | только 3–4 крупных блока с иконками |

### Темп и контраст (правила против «пяти одинаковых кадров»)

- Смена визуального состояния каждые **1.5–2.2 с**, иначе падает досмотр.
- **Правило чередования:** если сцена N текстовая/плоская, сцена N+1 обязана
  быть объёмной или анимированной. Это проверяет `node_variety_check`.
- 1–3 слова на экран для kinetic-типографики; предложение целиком читается
  дольше, чем длится сцена.

## 6.3. МИКРО-ПРИМИТИВЫ (конструктор вместо монолитов)

Сейчас каждый пресет — самодостаточный файл на ~164 строки, который сам рисует
фон, заголовок, подложку. Отсюда и однообразие: чтобы получить новый вид, надо
писать новый файл целиком.

Решение — слой примитивов, из которых сцена собирается:

```
remotion/src/primitives/
├── layout/     SafeArea, Stack, SplitH, SplitV, GridN, Corner
├── text/       AutoFitTitle, RevealText, CounterText, Marker
├── shape/      AnimatedPath, MorphShape, ArrowFlow, Underline
├── chart/      Axis, Bar, Line, Ring, Tick, Legend
├── three/      Camera, Lights, PointField, LayerMesh, GraphMesh
├── fx/         Glow, Grain, Vignette, ChromaticAberration, Bloom
└── motion/     springIn, staggerChildren, parallax, audioReact
```

Ключевые:

- **`AutoFitTitle`** — через `@remotion/layout-utils` меряет текст и подбирает
  кегль так, чтобы влезал в safe-area. Снимает вечную проблему длинного
  русского текста (в 1.5 раза длиннее английского).
- **`AnimatedPath`** — обёртка над `evolvePath`: любая линия рисуется по кадрам.
  На ней строятся `LineChart`, `ArrowFlow`, `Underline`, `SignalPath`.
- **`audioReact`** — `useAudioData` + `visualizeAudio`: масштаб/яркость
  элемента следуют за голосом. Дешёвый способ «оживить» статичную сцену.
- **`staggerChildren`** — каскадное появление списков вместо одновременного.

**Эффект:** новая сцена — это композиция примитивов на 30–40 строк, а не
164-строчный монолит. 37 недостающих сцен становятся реалистичной задачей.

## 6.5. ГРАФ СЦЕНАРИЯ (отдельный от графа рендера)

Сейчас сценарий пишется человеком в `STORYBOARD`, а граф только режет текст.
Нужен отдельный `msf/graph/script_graph.py`:

```
node_research        → факты со ссылками (LDR или fallback)
node_angle           → выбор угла подачи из 8 архетипов
node_beats           → разбивка на биты (не всегда 5!)
node_scene_match     → подбор сцены под каждый бит по типу данных
node_copy            → текст озвучки + экранный текст (разные!)
node_variety_check   → проверка на однообразие, переразбивка
node_emit_spec       → VideoSpec
```

### 8 архетипов структуры (вместо одного шаблона)

| Архетип | Скелет битов |
|---|---|
| `problem_solution` | боль → усугубление → решение → доказательство → CTA |
| `myth_bust` | распространённое мнение → почему неверно → как на самом деле → CTA |
| `number_story` | шокирующая цифра → откуда она → что значит → CTA |
| `how_it_works` | вопрос → механика по шагам → демонстрация → CTA |
| `comparison` | вариант А → вариант Б → критерий → вердикт → CTA |
| `timeline` | было → стало → куда идёт → CTA |
| `mistake_list` | ошибка 1 → ошибка 2 → ошибка 3 → как правильно → CTA |
| `build_along` | цель → шаги сборки → результат → CTA |

Число битов — 4–8, зависит от архетипа и объёма фактов, а не константа 5.

### Правило подбора сцены под бит

```python
# Псевдокод node_scene_match
```

### Решение: research-провайдеры за одним интерфейсом

```python
class ResearchProvider(Protocol):
    def research(self, query: str) -> ResearchResult: ...
    # ResearchResult: facts[], sources[], confidence
```

| Провайдер | Когда | Цена интеграции |

## 6.7. ГАЙДРЕЙЛЫ ПО УРОВНЯМ АГЕНТА — РЕЗУЛЬТАТЫ РЕАЛЬНОГО ТЕСТА

Пользователь просил: сначала выяснить, где агенты ошибаются, попробовать
починить документацией, и **только если не поможет** — резать функционал.

### Методика

Написан `audit/agent_error_probe.py`: 5 задач на авторинг спеки (счётчик,
сравнение, пайплайн, мультисцена, цитата), каждая прогоняется через модель,
результат валидируется **настоящей Zod-схемой** + семантические проверки.

Модели: `gemini-3.6-flash-medium`, `gemini-3.6-flash-high`.
(`gemini-3.6-flash-low` в роутере отсутствует, `gemini-3-5-pro` отдаёт 404 —
проверено запросом к `/v1/models` и вызовом.)

### Результат ДО правки документации

| Модель | Чистых спек | Провалы |
|---|---|---|
| `gemini-3.6-flash-medium` | **2 / 5** | statValue строкой ×2, steps массивом строк |
| `gemini-3.6-flash-high` | **2 / 5** | ровно те же три |

**Главное наблюдение: high не лучше medium.** Ошибки не от нехватки
«интеллекта» — обе модели выбирали правильный пресет и писали осмысленный
текст, но заполняли поля неверным типом:

```jsonc
"statValue": "6.8"                      // строка вместо числа
"steps": ["Текст", "Токены", "Векторы"] // строки вместо объектов
```

Это в точности те же две ошибки, которые допустил и я при ручной сборке
промо-роликов — то есть виноват контракт, а не исполнитель.

### Результат ПОСЛЕ правки документации

В бриф добавлен блок из 5 правил с парами WRONG/RIGHT:

| Модель | Было | Стало |
|---|---|---|
| `gemini-3.6-flash-medium` | 2 / 5 | **5 / 5** |
| `gemini-3.6-flash-high` | 2 / 5 | **5 / 5** |

Воспроизводится: `python audit/agent_error_probe.py --brief v1` против
`--brief v2`.

### Вывод: функционал НЕ режем

Раз документация закрывает 100 % наблюдаемых ошибок, ограничивать набор
пресетов для слабых моделей нет оснований. Вместо этого:

1. **Блок про типы внесён в скилл `msf-dumb-animate`** (сделано).
2. **Список пресетов в скилле исправлен с 5 на реальные 11** (сделано) — раньше
   скилл сам скрывал от агента 6 доступных пресетов.
3. **Zod pre-flight** (`remotion/validate_spec.mjs`) — ошибка ловится до
   рендера, с точным путём до поля (сделано).
4. **Post-render проверка кадра** — красный экран ошибки не может уехать как
   готовый ролик (сделано).
