# ПРИЛОЖЕНИЕ A К MASTER PLAN v5

## 20 сцен «широкого назначения», единый слой интерполяции, источники 3D-моделей

> Приложение к `docs/MASTER_PLAN_v5_SECTION6.md`. Возникло после разбора каталога
> из 48 сцен: заказчик указал, что сцены получились слишком узконаправленными,
> а настройки — избыточными и мелочными.
>
> Все технические факты в этом файле получены исполнением команд на этой машине:
> `npm view`, `require()`, `curl` с кодами ответа, распаковка заголовка GLB.
> Ничего не пересказано по памяти. Непроверенное помечено словом «требует проверки».

## A.0. ЧТО НЕ ТАК С ПРЕДЫДУЩИМ СПИСКОМ (замечания заказчика)

Три претензии, все справедливые:

| № | Замечание | Что делаем в этом приложении |
|---|---|---|
| 1 | **Избыточные настройки.** Флаги вроде `typoChance`, `punctuationPause`, `compressGaps` — мелочь, которой никто не воспользуется | Вырезаны. Список параметров сцены сокращён до тех, что меняют кадр заметно |
| 2 | **Сцены слишком узкие.** `GaugeMeter`, `TerminalType` решают одну задачу и больше нигде не применимы | Новый набор строится по принципу «носитель для любого контента»: облёт произвольной модели, карточки с произвольным текстом, график по произвольным данным |
| 3 | **Нет управления интерполяцией.** Кривые были зашиты в каждую сцену отдельными флагами (`swapEase`, `arcDrawEase`, `pullBackEase`) | Введён **единый слой `motion`** (раздел A.1). Один и тот же контракт для всех 20 сцен, доступен по каналам |

Требование заказчика, ставшее ограничением для всего приложения:

> Во всех сценах должны быть плавные анимации, мягкие интерполяции,
> умный агент должен иметь возможность гибко управлять интерполяцией.

Отсюда следует: **линейной интерполяции по умолчанию нет нигде**. Дефолт проекта —
`easeInOut` либо пружина с сильным затуханием. Резкие кривые (`bounce`,
`anticipate`, `stutter`) доступны, но включаются только явно.

## A.1. СЛОЙ `motion` — ЕДИНАЯ ИНТЕРПОЛЯЦИЯ

Ядро приложения. Любое анимируемое свойство любой сцены описывается одним и тем
же объектом. Это заменяет ~30 разрозненных `*Ease` / `*Speed` / `*Curve` флагов
из предыдущей версии списка.

### Контракт

```ts
type Motion = {
  curve?:
    | 'linear' | 'ease' | 'easeIn' | 'easeOut' | 'easeInOut'
    | 'spring' | 'bounce' | 'anticipate' | 'overdamped'
    | [number, number, number, number];   // произвольный кубический безье

  spring?: { damping?: number; stiffness?: number; mass?: number };

  duration?: number;      // кадры
  delay?: number;         // кадры
  stagger?: number;       // кадры между однотипными элементами
  staggerFrom?: 'first' | 'last' | 'center' | 'edges' | 'random';
  loop?: 'none' | 'pingpong' | 'repeat';
};
```

### Каналы

Умный агент задаёт `motion` отдельно по каналам — это и есть запрошенная гибкость:

| Канал | Что управляет |
|---|---|
| `motion.camera` | перемещение и доворот камеры в 3D-сценах |
| `motion.value` | набегание чисел, рост баров, заполнение дуг |
| `motion.reveal` | появление элементов, маски, прорисовка путей |
| `motion.transform` | масштаб, поворот, положение объектов |
| `motion.opacity` | прозрачность, гашение фона |

Если канал не задан — берётся `motion` сцены. Если и его нет — дефолт проекта.

### Дефолты проекта

```ts
const MOTION_DEFAULT = {
  curve: 'easeInOut',
  duration: 24,
  spring: { damping: 14, stiffness: 90, mass: 1 },
};
```

`damping: 14` подобран как «мягкая пружина без дрожи»: овершут заметен, но
колебание гаснет за один период. **Требует проверки на рендере** — цифра взята
как разумный старт, а не измерена.

### Пресеты для слабого агента

Слабая модель не должна вычислять кривые. Ей доступен один параметр
`intensity`, который раскрывается в готовый `motion`:

| `intensity` | Раскрывается в | Ощущение |
|---|---|---|
| `calm` | `easeInOut`, `duration: 40`, `stagger: 6` | медленно, дорого, для цитат и данных |
| `normal` | `easeOut`, `duration: 24`, `stagger: 4` | базовый темп |
| `punchy` | `spring{damping:12, stiffness:140}`, `duration: 18`, `stagger: 3` | энергично, для хуков |
| `extreme` | `anticipate`, `duration: 12`, `stagger: 2` | агрессивно, только для 1–2 сцен в ролике |

Связь с гайдрейлами из раздела 6.7: слабый агент (уровень ≤ 2) получает **только**
`intensity`. Поле `motion` для него закрыто валидатором — иначе он присылает
безье с координатами вне диапазона.

## A.2. ОБЩИЙ СЛОЙ НАСТРОЕК (все 20 сцен)

Не повторяется в описании каждой сцены.

| Параметр | Значения | Назначение |
|---|---|---|
| `style` | 8 арт-направлений (A.3) | палитра + типографика + поверхность + зерно |
| `accent` | hex | перебивает акцент стиля |
| `colorMode` | `dark` / `light` / `inverted` | инверсия стиля |
| `intensity` | `calm` / `normal` / `punchy` / `extreme` | пресет `motion` |
| `motion` | объект A.1 | точное управление (только умный агент) |
| `density` | `bare` / `minimal` / `normal` / `rich` | объём декора: сетки, частицы, плашки |
| `transitionIn` | 20 переходов из `@remotion/transitions` | склейка с предыдущей сценой |
| `safeArea` | `platform` / `loose` / `custom` | отступы под UI платформы |
| `seed` | число | детерминирует «случайное»: раскладку частиц, дрейф |
| `emphasis` | `string[]` | слова, подсвечиваемые акцентом |

`seed` — рабочая лошадка разнообразия: одна сцена с разным сидом даёт другую
раскладку и микро-дрейф, оставаясь воспроизводимой при повторном рендере.

## A.3. ВОСЕМЬ СТИЛЕЙ

Стиль меняет **пять осей сразу**, а не только цвета. Текущие 5 тем в
`remotion/src/presets/brand.ts` меняют лишь палитру — отсюда ощущение однообразия.

| Стиль | Палитра | Типографика | Поверхность | Характер движения |
|---|---|---|---|---|
| **Pop-Laboratory** | кислотный акцент на графите | гротеск, вес 800 | плашки с толстой обводкой | пружина с овершутом |
| **Noir Terminal** | фосфорный зелёный / янтарь на чёрном | моноширинный | скан-линии CRT | щелчками по кадрам |
| **Frosted Glass** | пастель на тёмном | тонкий гротеск | блюр подложки 20–40 px, бордер 1 px | длинный `easeOut` |
| **Blueprint** | синяя калька, белые линии | узкий технический | штриховка, размерные выноски | прорисовка линии |
| **Brutalist Print** | чёрное на белом | плотный трекинг | рамки 6–8 px, офсет слоёв 4–6 px | мгновенные сдвиги |
| **Synthwave Neon** | пурпур / циан на фиолетовом | широкий с свечением | сетка-горизонт, bloom, аберрация | бесконечный скролл |
| **Swiss Editorial** | белый фон, одна акцентная плашка | Helvetica-подобный | модульная сетка, большие поля | только вход текста |
| **Holo Iridescent** | градиент циан→пурпур→золото по нормали | тонкий | стеклянные объёмы | медленный орбит |

**Комбинаторика:** стиль не привязан к сцене. 20 сцен × 8 стилей = 160 разных
кадров без единой новой строки компонента.

## A.4. ДВАДЦАТЬ СЦЕН

Принцип отбора: **сцена — носитель, а не иллюстрация конкретного факта**. В любую
подставляется произвольный контент, поэтому одна сцена переиспользуется в роликах
на несовместимые темы.

Ни одна из 20 не реализована в текущем коде. Ближайшие существующие родственники
указаны в колонке «родня».

### Группа 1 — сформулированы заказчиком (5 сцен)

#### 1. `ModelOrbit3D` — облёт скачанной 3D-модели

Реальная модель `.glb` в центре кадра, камера идёт вокруг, студийный свет.
Родня: нет. Зависимость: `@react-three/drei` (не установлен, см. A.6).

| Параметр | Значения |
|---|---|
| `modelUrl` | прямая ссылка, `khronos:DamagedHelmet`, либо локальный путь |
| `orbit` | `full360` / `arc` / `figureEight` / `dolly` |
| `orbitDegrees`, `startAngle`, `elevation` | геометрия облёта |
| `autoFrame` | авто-подгон камеры по габаритам (через `THREE.Box3`) |
| `spinModel` | вращать модель вместо камеры либо вместе |
| `lighting` | `studio` / `rim` / `dramatic` / `hdri` / `neon` |
| `env` | `none` / `gradient` / `grid` / `hdri` |
| `groundShadow` | `off` / `soft` / `contact` |
| `material` | `original` / `clay` / `glass` / `wireframe` / `xray` |
| `hotspots[]` | метки с подписями, всплывают когда камера смотрит на них |

Интерполяция: `motion.camera` с `easeInOut` и большой `duration` даёт «дорогой»
облёт; `linear` в облёте выглядит механически и запрещён дефолтом.

#### 2. `BeforeAfter` — до и после

Два состояния с картинками под подписями. По уточнению заказчика основной режим —
**последовательный**: сначала кадр «до», затем кадр «после», а не рядом.
Родня: нет (существующий `CompareSplit` показывает одновременно).

| Параметр | Значения |
|---|---|
| `mode` | `sequential` (дефолт) / `wipe` / `sideBySide` / `stackVertical` |
| `beforeMedia`, `afterMedia` | изображение или видео |
| `beforeLabel`, `afterLabel` | подписи |
| `holdBefore`, `holdAfter` | кадры выдержки на каждом состоянии |
| `revealStyle` | `crossDissolve` / `wipeLR` / `wipeTB` / `zoomThrough` / `glitchCut` |
| `deltaBadge` | плашка улучшения: `+340 %`, `−12 s` |
| `zoomOnDetail` | прямоугольник, к которому камера подъезжает **одинаково** на обоих кадрах |
| `verdict` | итоговая строка |

Одинаковый `zoomOnDetail` на обоих состояниях — обязателен: если ракурсы разные,
разница не читается.

#### 3. `TradingChart` — растущий график

Свечи или линия как на бирже, ось Y подстраивается за ценой.
Родня: нет (в каталоге 6.2 заявлен `LineChart`, не реализован).

| Параметр | Значения |
|---|---|
| `chartType` | `candles` / `line` / `area` / `mountain` |
| `series[]` **или** `generate{trend, volatility, points}` | реальные данные либо процедурная генерация |
| `revealMode` | `leftToRight` / `live` (строится как тикер) |
| `yAxisMode` | `autoFollow` / `fixed` |
| `priceTag` | бегущее значение у последней точки |
| `pumpMoment` | кадр резкого выброса + тряска + вспышка |
| `drawdown` | допустить просадку перед ростом (правдоподобность) |
| `annotations[]` | выноски на конкретных точках |
| `volumeBars`, `glowTrail`, `gridStyle` | декор |

Интерполяция: `motion.value` с `overdamped` — рост солидный, без дрожания на
последней точке.

#### 4. `DonutFill` — бублик, медленно набирающий проценты

Сегменты заполняются от нуля до своих значений. По уточнению заказчика —
одновременно и медленно. Родня: нет. Внешних зависимостей нет.

| Параметр | Значения |
|---|---|
| `segments[{label, value, color?}]` | 2–6 штук |
| `shape` | `donut` / `pie` / `ring` / `halfDonut` / `nested` |
| `thickness` | толщина кольца |
| `fillMode` | `simultaneous` (дефолт) / `sequential` / `clockSweep` |
| `centerContent` | `total` / `leader` / `label` / `icon` / `empty` |
| `labelPlacement` | `outside` / `inside` / `legend` / `callout` |
| `percentCounters` | цифры у сегментов тикают синхронно с заливкой |
| `gapAngle` | зазор между сегментами |
| `highlightSegment` | какой выдвинуть |

Интерполяция: `motion.value` = `easeOut`, `duration: 60`. Счётчики процентов
обязаны использовать **ту же** кривую, что и заливка, иначе цифра и дуга
расходятся — это заметно глазом.

#### 5. `CardScatter3D` — карточки в 3D, камера ходит между ними

Карточки со скруглёнными краями расставлены в объёме произвольно, в том числе
позади камеры. Камера плавно переводит взгляд с одной на другую.
Родня: нет. Зависимость: `@react-three/drei` для теней и окружения.

| Параметр | Значения |
|---|---|
| `cards[{title, body?, icon?, media?}]` | контент |
| `arrangement` | `sphere` / `random` / `spiral` / `wall` / `cluster` / `manual` |
| `spread` | разброс в пространстве |
| `allowBehindCamera` | развороты на 180° и больше |
| `visitOrder` | `sequential` / `nearest` / `random` / `manual[]` |
| `dwellFrames` | сколько задержаться на карточке |
| `travelStyle` | `flyTo` / `orbitTo` / `snapTo` / `driftBy` |
| `cardRadius`, `cardMaterial` (`glass`/`matte`/`glow`/`paper`), `cardTilt` | вид карточки |
| `depthFog`, `dof` | дальние карточки в дымке и размытии |
| `activeCardEffect` | `scaleUp` / `glowEdge` / `faceCamera` / `lift` |
| `idleDrift` | карточки покачиваются, пока камера едет |

Ключевое для плавности: **`motion.camera` разделён на перемещение и доворот
взгляда**. Если доворот идёт по той же кривой, что и полёт, картинка «рыскает».
Взгляд должен приходить в цель раньше позиции — `motion.camera.lookAt` с меньшей
`duration`, чем `motion.camera.position`.

### Группа 2 — предложены дополнительно (15 сцен)

#### 6. `ExplodedView3D` — модель разбирается на части
Компоненты разлетаются, каждый с подписью, затем сборка обратно.
`modelUrl`, `explodeDistance`, `explodeAxis`, `partLabels[]`, `sequence` (`all`/`oneByOne`), `reassemble`, `focusPart`.

#### 7. `LayerPeel3D` — слои снимаются один за другим
Стек плоскостей, верхние отъезжают, обнажая нижние. Для «под капотом»: UI → API → модель → железо.
`layers[{label, color?, media?}]`, `peelDirection`, `peelStyle` (`slide`/`flip`/`dissolve`/`liftAway`), `tilt`, `spacing`, `holdPerLayer`, `highlightLayer`.
Родня: заявленный в 6.2 `LayerStack3D` (реализован) — эта сцена его развитие.

#### 8. `CounterGrid` — сетка метрик, набирающих значения
2×2 или 3×2 плитки, цифры тикают с разными задержками.
`tiles[{value, label, suffix?, trend?}]`, `grid`, `tickStyle` (`smooth`/`odometer`/`flip`), `trendArrows`, `highlightTile`.
Разброс задаётся `motion.value.staggerFrom` — `center` и `edges` смотрятся лучше `first`.
Родня: `StatCounter` (реализован, одна цифра).

#### 9. `MorphShape` — форма перетекает в другую
Через `interpolatePath` из `@remotion/paths`: логотип → график → иконка.
`shapes[]` (пути или пресеты), `holdPerShape`, `strokeOnly`, `drawIn`, `trailGhost`, `colorPerShape`.

#### 10. `TextMask` — текст как окно в видео
Огромные буквы, внутри видно видео или 3D-сцену.
`text`, `media`, `maskMode` (`textAsWindow`/`textAsCutout`), `zoomInside` (медленный зум подложки внутри букв), `strokeOutline`, `letterStagger`.

#### 11. `PhoneMockup` — интерфейс в рамке телефона
3D-корпус, внутри скриншот или запись экрана, лёгкий наклон.
`screenMedia`, `deviceStyle`, `deviceAngle`, `handheldSway`, `screenGlow`, `tapIndicators[]`, `scrollScreen`, `zoomToRegion`.
`handheldSway` реализуется через `@remotion/noise` (установлен) — детерминированное покачивание по `seed`.

#### 12. `StackRank` — рейтинг, который перестраивается
Элементы меняются местами с плавным переездом. Для «топ-5 моделей за год».
`items[{label, value, logo?}]`, `frames[]` (состояния рейтинга), `showDeltas`, `highlightRise`, `crownTop`.
Интерполяция: `motion.transform` с пружиной; перестановка по `linear` читается как баг.

#### 13. `HeatSweep` — матрица с бегущей подсветкой
Волна интенсивности по сетке. Для attention-карт, покрытия тестами, нагрузки.
`matrix[][]` либо `generate{rows, cols, pattern}`, `sweepDirection`, `cellShape`, `colorScale`, `zoomCell`, `pulseOnPeak`.
Ограничение из 6.2.1: на телефоне читается сетка **не мельче 8×8**.

#### 14. `SplitCompare3D` — два 3D-объекта бок о бок
Две модели на постаментах, камера обходит обе, метрики под каждой.
`leftModel`, `rightModel`, `metrics[]`, `orbitMode` (`aroundBoth`/`alternate`), `pedestalStyle`, `winnerHighlight`, `scaleToMatch`.
`scaleToMatch` обязателен: модели из разных источников приходят в разных единицах, без нормировки одна будет вдвое крупнее без смысла.

#### 15. `FlowPipeline` — конвейер с движущимися пакетами
Станции, между ними едут пакеты данных и преобразуются.
`stations[{label, icon?}]`, `packetStyle`, `packetRate`, `transformAt[]`, `bottleneckStation`, `throughputCounter`.
Родня: `FlowDiagram` (реализован, статичный).

#### 16. `QuoteReveal` — цитата с автором
Текст проявляется маской, аватар и должность подъезжают, фон дрейфует.
`quote`, `author`, `role`, `avatar`, `revealMode` (`byWord`/`byLine`/`mask`), `quoteMarks`, `bgDrift`, `sourceBadge`.
Родня: `QuoteCard` (реализован, без анимации проявления).

#### 17. `NumberScrub` — цифра меняется по шкале
Слайдер едет, значение пересчитывается. Для «8 GB VRAM → 3 t/s, 24 GB → 40 t/s».
`scrubFrom`, `scrubTo`, `mapping[]`, `unitLabel`, `pauseAtPoints`, `thresholdMarks`.
`pauseAtPoints` — единственный случай, где допустима негладкая кривая: остановки на ключевых точках несут смысл.

#### 18. `ChecklistTick` — пункты отмечаются
Список требований, каждый получает галочку или крестик.
`items[{text, status}]`, `tickStyle` (`check`/`stamp`/`draw`/`fill`), `failStyle`, `progressBar`, `summaryLine`.

#### 19. `GlobeArcs` — глобус с дугами трафика
Точечная сфера, дуги между городами прорисовываются, маркеры пульсируют.
`points[{lat, lon, label?}]`, `arcs[{from, to, weight?}]`, `globeStyle` (`dots`/`wireframe`/`textured`), `rotation`, `focusRegion`, `nightLights`.
Прорисовка дуг — через `evolvePath` (`@remotion/paths`, установлен).

#### 20. `EndCardOrbit` — финальная плашка в 3D
Название канала в объёме, камера отъезжает, вокруг облетают тезисы ролика.
`title`, `subtitle`, `bullets[]`, `logoModel`, `bulletOrbitSpeed`, `ctaBadge`, `loopSeam`.
`loopSeam` стыкует последний кадр с первым — ролик зацикливается без рывка, что
поднимает досматриваемость на платформах с автоповтором.

## A.5. ИСТОЧНИКИ 3D-МОДЕЛЕЙ — ПРОВЕРЕНО ЗАПРОСАМИ

Заказчик снял требование по лицензиям («используем любые бесплатно доступные к
скачиванию»). Юридический вопрос закрыт, но остался **технический**: часть
каталогов не отдаёт файл без ключа.

| Источник | Код ответа | Пригодность |
|---|---|---|
| **Khronos `glTF-Sample-Assets`** | `200` на прямой GLB | ✅ основной. Без ключа, прямые ссылки |
| **Khronos `glTF-Sample-Models`** | `200`, **104 модели** в каталоге `2.0` | ✅ основной |
| **Quaternius** | `200` | ✅ CC0-паки: техника, природа, персонажи |
| **Kenney** | `200` | ✅ CC0: низкополигональные пропсы |
| Sketchfab API `/v3/search` | `200`, поиск работает | ⚠️ поиск да, загрузка нет |
| Sketchfab `/v3/models/<uid>/download` | **`401`** | ⛔ нужен OAuth-токен |
| Poly Pizza API `/v1.1/search` | **`401`** | ⛔ нужен API-ключ |

### Проверка сквозного пути

Скачан `DamagedHelmet.glb` и разобран заголовок:

```
downloaded HTTP 200  size=3773916
magic: glTF | glTF version: 2 | declared bytes: 3773916 | actual: 3773916
VALID GLB: True
```

Загрузчик в среде проекта:

```
GLTFLoader loads in node: true
three version: 169
Box3 (for autoFrame): true
```

Вывод: путь «скачать → загрузить → закадрировать» рабочий целиком, без ключей.

### Решение: провайдеры моделей за одним интерфейсом

По аналогии с `ResearchProvider` из 6.6:

```
ModelProvider
  ├── KhronosProvider    (дефолт, без ключа)   khronos:DamagedHelmet
  ├── QuaterniusProvider (без ключа)           quaternius:tank
  ├── KenneyProvider     (без ключа)           kenney:server-rack
  ├── UrlProvider        (прямая ссылка)       https://…/model.glb
  └── SketchfabProvider  (опционально, токен)  sketchfab:<uid>
```

Кеш в `assets/models/<provider>/<id>.glb` — модели не тянутся по сети на каждый
рендер. Для справки: сравнение лицензий среди 20 загружаемых моделей Sketchfab
(CC-BY 14, CC-BY-NC 4, CC-BY-NC-ND 1, CC-BY-ND 1) сохранено в истории, но
фильтр по лицензии по решению заказчика **не реализуется**.

## A.8. ПОРЯДОК РАБОТ ПО ПРИЛОЖЕНИЮ A

Порядок подчинён одному правилу: **сначала инфраструктура, потом сцены**. На слое
примитивов (6.3) каждая сцена — 30–40 строк вместо 164-строчного монолита.

| № | Шаг | Проверка результата |
|---|---|---|
| 1 | `motion`-слой: `resolveMotion()` + пресеты `intensity` | юнит-тест: все 4 `intensity` дают валидные кривые |
| 2 | `SafeArea` и устранение расхождения отступов (см. ниже) | ни один текст не заходит в зону UI платформы |
| 3 | `DonutFill` — первая сцена, без внешних зависимостей | цифры процентов совпадают с углами дуг по кадрам |
| 4 | Установка `@react-three/drei@9` | `require.resolve('@react-three/drei')` проходит |
| 5 | `ModelProvider` + кеш `assets/models/` | `khronos:DamagedHelmet` рендерится из кеша офлайн |
| 6 | `ModelOrbit3D` на DamagedHelmet | `autoFrame` держит модель в кадре все 360° |
| 7 | `CardScatter3D` с раздельными кривыми позиции и взгляда | нет рыскания камеры при переводе между карточками |
| 8 | Остальные 17 сцен пачками по 3–4 | `npx tsc --noEmit` = 0 после каждой пачки |
| 9 | Регистрация всех сцен в `ALLOWED_PRESETS` и Zod-схеме | `agent_error_probe.py` ≥ 90 % чистых спек на полном каталоге |

### Незакрытый баг, найденный при проверке (повтор из 6.8, шаг 2)

**Три несогласованных набора safe-margins:**

| Где | Значения |
|---|---|
| `remotion/src/VideoSpec.schema.ts` | `safeMargin: 120` (проверено) |
| `msf/libraries/typography_library.py` | `top 140 / bottom 240`, **не подключён к графу** |
| Требование платформ | `bottom ≈ 380` (ник, подписи, кнопки) |

Ни один вариант не защищает низ кадра. Пока не исправлено, подписи в новых сценах
будут упираться в интерфейс платформы — поэтому шаг 2 идёт раньше любых сцен.

### Критерий приёмки приложения

Три ролика на одну тему, сгенерированные подряд, не совпадают ни по набору сцен,
ни по стилю, ни по структуре битов. Ни в одном ролике нет линейной интерполяции
там, где не задана явно. Проверка — `vision_analyze` по полосе кадров плюс
покадровая сверка счётчиков со значениями в спеке.
