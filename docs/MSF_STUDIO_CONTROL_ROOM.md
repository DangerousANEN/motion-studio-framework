# MSF Studio Control Room

## Purpose

Studio Control Room is the local operator surface for the existing MSF worker. It makes the pipeline observable and editable **without** exposing chain-of-thought, secrets, private media paths, or unbounded arbitrary code execution.

The dashboard works against the canonical Studio run lifecycle: draft → validate → queue → worker → complete/failed. It does not create a second renderer or a second graph.

## Visual layout

| Area | Operator job | Data source |
|---|---|---|
| Command bar | Create/choose a run, start approved work, cancel a running job | Studio run API |
| Pipeline graph | See graph nodes, dependencies, status, current node and safe activity label | Static graph definition + live run endpoint |
| Node inspector | Read purpose, inputs/outputs, editable operator instruction, latest event and artifacts | Safe node metadata + event stream |
| Scene library | Browse scene cards, cached previews, intent/data requirements and sound roles | Live catalog + preview cache |
| Scene drawer | Play a preview, inspect fields, choose preset, alter only compatible draft props | Manifest + `/api/preview/scene` / `/api/preview/clip` |
| Draft editor | Edit topic, preset, style config, research/music/SFX flags and bounded node instructions before approval | Draft request patch API |
| Event rail | Follow status, current activity, diagnostics and redacted trace spans | Cursor-based run timeline |

## Truthful live status

The canonical graph contains: `gate_check` → `deep_research` → `script_split` → `voice_synthesis` → `soundtrack` → `build_spec` → `render` → `master_audio` → `qa`, with a repair branch back to `render` only after failed QA.

The worker emits `node.started`, `node.completed`, `node.failed`, `artifact.created`, run lifecycle events and a snapshot `current_node`. The UI polls the incremental timeline only while a run is queued/running. This is real operational telemetry, not a reconstruction from a timer.

> Remotion renders a complete composition rather than issuing a reliable callback for a named scene. During `render` the dashboard shows the exact composition scene count and the current composition stage, but must not pretend to know a per-scene render index unless the renderer actually reports one.

## Safe operator control

Draft-only patches are allowed for: topic, preset, style/style config, research flag, music flag, SFX flag, voice selector and agent level. The operator can also edit **bounded public instructions** assigned to nodes such as research focus, script style and scene-selection constraints. They become a versioned `operator_overrides` artifact and are visible in events.

The panel rejects request patches after approval/start, rejects unknown node IDs, arbitrary executable payloads, hidden prompt replacement, raw credentials, private paths and renderer code changes. To alter a running job, the operator may cancel it and create a revised draft.

## Community and media policy

Scene previews are generated by the existing resident Remotion preview service and cached locally. The dashboard may show source metadata and review status for community leads, but third-party YouTube/X/Reddit media remains attribution-only until a human supplies/approves licensed media.

## Transport and persistence

The initial local-first implementation uses short client polling of a cursor-based timeline while a run is active. It does not need a permanent realtime broker or a background polling process: the browser asks for new events only when Control Room is open. A future hosted deployment may upgrade the same endpoint to SSE/WebSocket without changing the artifact contract.
